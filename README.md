# 问道 WenDao

个人全维度 AI 规划助手。根据你的身体、饮食、财务、生活状态，AI 智能规划健身训练、饮食计划和财务方案，全程跟踪、每日建议、定期总结。

## ✨ 核心特色

### 🧠 本地智脑（RAG）
- 纯算法检索（BM25 式打分 + 中文滑窗分词），无需本地 AI、无需好硬件
- 书籍全文 + 大师知识库 + 个人数据统一索引，秒级检索
- 预索引缓存 + 场景过滤 + 片段截断，Token 消耗降 50%+

### 🏯 道法术养行五层融合体系
- **道**｜训练哲学：阴阳平衡、专气致柔、反者道之动、缘督以为经
- **法**｜训练分期：筑基（体态纠正）→ 进阶（力量提升）→ 化境（意念控制）
- **术**｜动作设计：每动作关联经络 + 筋膜链 + 穴位 + 呼吸法 + 导引术
- **养**｜恢复养生：穴位按压、八段锦/易筋经放松、中医食疗配合
- **行**｜生活节律：四季侧重、子午流注、情绪匹配、起居作息

### 💪 健身训练
- 苗振（诺亚第）体系：316呼吸法、犁式呼吸、三腔对位、脊柱中正
- 器械感知：AI 根据健身房实际器械实时调整，缺器械自动变通替换
- 训练记录跟踪，根据今日表现自动排下次方案

### 🥗 饮食营养
- 饮食记录 + 热量计算
- 中医食疗（四气五味归经）与运动营养结合

### 💰 财务规划
- 收支记录、预算管理、超支预警
- 资产持仓（基金/ETF）与负债（花呗等）管理
- 微信/支付宝账单 CSV 导入
- 巴菲特 / 芒格 / 舍费尔 / 纳瓦尔 / 小而美大师智慧注入

### 🌿 中医与历法
- 身体评估：BMI / 体脂率 / 安全减脂预估
- 生活状态记录（压力/精力/睡眠），情绪匹配训练类型

### 🌐 联网搜索
- 微信公众号 / Bing / 百度多源搜索，AI 综合分析

### ☁️ 云同步与账号（P2）
- 邮箱注册登录，FastAPI 云端（SQLite/加密备份）多端同步
- 本地 SQLCipher 加密缓存，离线全功能可用，联网自动同步
- 写入防抖批量推送 + 指数退避重试，拉取游标翻页续传
- 冲突服务器时间戳裁决（LWW），多端改动不丢不重
- 生物识别 / 6 位 PIN 应用锁，回后台超时自动重锁
- 一键清除本地数据（云端保留，可随时重新拉取）

### 🤖 AI 智能体（P3）
- 数据感知的 Agent 对话：模型先调用本地工具查真实数据再回答，绝不编造
- 21 个只读内置工具：身体档案 / 今日摘要 / 训练记录 / 饮食记录 / 财务概况 / 健康指标 / 知识库检索 / 生活状态 + 循证 4 工具（证据检索 / MET / 动作 / 食物营养）+ 穿戴摘要 + 文献检索（`search_literature`，需开启联网）+ 疾病运动（`search_condition_exercise`，疾病—运动两层关联）+ 用药安全（`search_otc_safety`，家庭用药安全常识）+ 补剂常识（`lookup_supplement`，核心膳食补充剂常识）+ 本体术语（`query_ontology`，EXMO / RehabO 原始术语）+ 开放动作库（`query_exercise_catalog`，2428 条）+ 数据源登记表（`list_open_datasets`，仅元数据与获取指引）+ 体检报告（`get_health_reports`，P7 健康档案：列表 / 单份详情 / 行动清单）（全部复用本地 Provider，无需额外接口）；另有 4 个写工具（产 `PendingAction`、经确认后落库）
- Agent 循环上限 6 轮自动收敛，工具结果超长截断，上下文窗口 24 条裁剪，Token 可控
- 模型不支持 function calling 时自动降级"简化模式"：个人数据注入上下文直接问答
- 聊天页：工具执行状态实时展示、快捷指令、会话持久化与一键新会话

### 📖 循证知识库与循证问答（P4-A / P4-B）
- 内置循证知识库 `assets/data/evidence_kb.json`：运动处方（FITT）、疾病-运动对照、MET 强度分级、运动损伤与禁忌，每条证据附**出处与证据等级**
- 证据条目模型 `EvidenceEntry` + 导入脚本 `scripts/import_knowledge.py`，本地离线可用
- 智能体新增 4 个循证工具：`search_medical_evidence`（证据检索）/ `query_met`（MET 与强度分级）/ `query_exercise`（动作查询）/ `lookup_food`（食物营养）
- 回答遵循**循证引用规范**：给出结论必附指南出处与证据等级，绝不编造文献

### 📚 文献检索与疾病—运动关联知识库（P5）
- **开源文献检索** `search_literature`：接入 Europe PMC、OpenAlex、Crossref、Semantic Scholar 四个开放接口，按关键词返回**文献元数据**（标题 / 期刊 / 年份 / DOI / 链接），仅元数据、不下全文；需在设置中开启联网
- **公开网页检索** `web_search`：接入 AnySearch 官方检索 API（Bearer 鉴权、非抓取结果页），仅取**标题 / 链接 / 摘要片段**，解析阶段丢弃接口返回的正文；Key 存系统加密存储（Keystore / Keychain），默认关闭，需在「设置 → 联网检索」开启并配置 Key。客户端自设两道闸门：按本地日期计数、**每天上限 2000 次**（对应学生 / 开发者免费额度），以及两次请求最小间隔 1.2 秒，额度用尽当天不再外发请求，剩余次数在设置页可见
- **疾病—运动关联库（两层证据结构，纯离线，零网络依赖）**：工具 `search_condition_exercise` 回答「某疾病 / 人群适合什么运动」，并能进一步给出**具体动作示例**
  - 第一层（强证据）：疾病 / 人群 → 运动类别 + **FITT-VP 剂量**，`domain='疾病运动'`，来源为权威指南（PAG 2018 / WHO 2020 / ACSM / 中国《人群身体活动指南(2021)》等）
  - 第二层（弱证据）：运动类别 → **具体动作示例 + 一般性禁忌**，仅供「选动作」参考，**不含任何疗效主张**
- **禁止证据越级（硬约束）**：绝不说「硬拉改善高血压」这类把具体动作与疾病疗效直接挂钩的表述；约束同时写入 `system prompt` 与工具输出的固定免责段，输出固定「先强证据、后弱证据」两段分离
- 动作库主表取自开放动作库（free-exercise-db / exercises-dataset / longhaul-fitness 等多源，均为公共领域或 MIT 许可），中文名与要点为自撰改写；**构建期已剥离全部媒体**（不收录任何图片 / 动图）
- 每条结论强制带出处；未命中时如实返回「本地库暂无该疾病的运动关联条目，建议咨询医生或康复治疗师」，**绝不编造**；所有运动建议均附禁忌人群与就医提示

### 💊 家庭用药安全知识库（P6-A）
- **纯离线家庭用药安全库**：工具 `search_otc_safety` 回答「退热 / 止咳 / 鼻塞 / 咽痛 / 胃肠不适」等常见场景的用药禁忌、联用风险、特殊人群与就医提示，零网络依赖
- 内置 64 条、8 组（退热镇痛 / 中成药退热 / 咽痛 / 止咳化痰 / 干咳 / 鼻部症状 / 恶心呕吐 / 用药安全通识），数据落于 `assets/data/evidence_kb.json` 的 `otcSafety[]`
- **独立证据等级口径**：用药安全条目性质为「官方文件规定」与「说明书范本」，不适配临床三级分级，故单设白名单 `指南`（官方文件）＞`专家`（NMPA 说明书范本）；与循证库 `指南推荐/系统评价/RCT` 互不干扰
- **两条官方来源**：国家卫健委《新冠病毒感染者居家治疗常用药参考表》（2022-12-08）、国家药监局《第二批国家非处方药化学药品使用说明书目录》，仅条目化改写，不复制整篇说明书
- **安全边界（硬约束，写入 system prompt 与工具输出）**：只给用药安全常识，不作诊断、不开处方、不给个体化剂量（儿童 / 孕产 / 哺乳 / 老年 / 慢病人群仅给「禁用 / 慎用 / 遵医嘱」）；每条必附出处；出现胸痛 / 呼吸困难 / 意识改变 / 呕血黑便 / 高热不退 / 严重过敏等**红旗症状**时首要建议尽快就医；未命中时如实说明无本地依据，**绝不编造药品、成分或规定**
- 检索严格限定 `domain='用药安全'`，防止用药安全结论外溢到循证 / 疾病运动等其他域

### 🧪 核心膳食补充剂知识库（P6-C）
- **纯离线补剂常识库**：工具 `lookup_supplement(query, topic?)` 回答「某补剂是什么 / 推荐摄入量 / 可耐受最高摄入量 / 一般性安全提示与相互作用」，零网络依赖
- 内置 24 条、11 组（维生素 D / Omega-3 / 镁 / 锌 / 铁 / 钙 / 维生素 C / 复合维生素 / 肌酸 / 乳清蛋白 / 咖啡因），数据落于 `assets/data/evidence_kb.json` 的 `supplements[]`
- **独立证据等级口径**：补剂条目性质为「官方文件」与「专业学会共识」，单设白名单 `指南`（NIH ODS / FDA 官方文件）＞`专家`（ISSN / EFSA 专业学会共识）；与循证库、用药安全库互不干扰
- **两条来源族**：美国国立卫生研究院膳食补充剂办公室（NIH ODS）消费者事实清单 8 篇、美国食品药品监督管理局（FDA）咖啡因消费者资讯；运动营养类补充国际运动营养学会（ISSN）立场声明 3 篇、欧洲食品安全局（EFSA）咖啡因安全性科学意见 1 篇。均为公共领域或开放许可（美国联邦作品 17 U.S.C. §105 / CC BY 4.0），仅条目化改写，不复制整篇原文
- **安全边界（硬约束，写入 system prompt 与工具输出）**：只给成分 / 参考摄入量 / 上限 / 一般性安全提示，**不作诊断、不开个体化补充方案、不承诺疗效**；**官方参考值类补剂不得出现体重换算式剂量**（`mg/kg`）；涉及孕妇 / 哺乳 / 儿童青少年 / 老年 / 慢病人群时**必须引导至医师或药师**；每条必附出处与链接；未命中时如实说明无本地依据，**绝不编造成分、剂量或出处**
- 检索严格限定 `domain='补剂'`，防止补剂结论外溢到循证 / 疾病运动 / 用药安全等其他域；固定免责话术随每条输出附上（保健食品不是药物，不能代替药物治疗疾病）
- 数据源调研与许可核验：`docs/research/2026-10-08-supplement-database-research.md`（DSLD / ODS / LNHPD / OFF 四源核验结论与静态导入推荐）

### 🧬 开放数据与本体接入（P6-D）
- **三类开放标准全部离线接入**：构建期静态导入、App 内零网络依赖，只取上游官方发布的开放文件，不写任何抓取第三方站点的脚本
- **本体术语 433 条**：运动医学本体 EXMO（370 条，CC BY 4.0，须署名）+ 康复本体 RehabO（63 条，CC0，取自 OBO Foundry）。工具 `query_ontology(query, ontology?)` 回答「某术语什么意思 / 与父类的关系」；**术语原样搬运、不翻译、不改写、不推断**，只保留 id / 标签 / 同义词 / 定义 / 父类，输出显式标注「原始术语，未翻译」，避免自造译名污染语义标准
- **开放动作库 2428 条**：Exercises Dataset（1324 条）+ Free Exercise DB（738 条）+ Longhaul Exercises（366 条，MIT）归并，覆盖目标肌群 / 协同肌群 / 部位 / 器械 / 难度 / 文字说明。工具 `query_exercise_catalog(body_part?, equipment?, keyword?, zh_only?)` 按部位、器械或关键词检索；**构建期已剥离全部媒体字段**（图片 / 动图 / 视频均不收录，版权属原作者），中文说明取上游提供的中文，非本应用翻译
- **数据源登记表 82 条**：工具 `list_open_datasets(keyword?, kind?, access?)` 提供开放数据源（本体 / 数据集 / 知识图谱 / 开源软件 / 食品数据库）的元数据与获取指引，**只承载元数据、不含任何正文数据**；`access` 分「已接入 / 可接入 / 登记题录」三态，仅前两态可用于检索，登记题录明确标注「本地未入库任何数据，不得当作已有数据引用」
- 体量最大的动作库拆为独立资产 `assets/data/exercise_catalog.json`（约 2 MB）并按需加载，不拖慢启动；新增浏览页「开放数据与本体」（本体术语 / 数据源登记表 / 开放动作库三分区），入口在设置页
- 单测 `test/open_data_test.dart` 25 项守住三条硬约束（不翻译 / 登记题录不得当数据用 / 媒体字段零收录），并对构建期产物做规模、去重与字段完整性断言

### ⌚ 运动健康数据接入（P4-C）
- 通过 `health` 插件只读接入 Android **Health Connect** / iOS **HealthKit**：小米运动健康、第三方体脂秤等 App 写入的数据可被汇聚读取（零平台审核）
- 读取步数/距离/活动热量、心率/静息心率/HRV、睡眠分期、体重/体脂/肌肉量、血氧/血压/血糖、锻炼记录共 15 类，**逐类型只读授权**
- `WearableProvider`：授权管理、近 30 天同步、本地快照（按"类型+时间戳"去重）、数据源逐类型诊断
- 智能体工具 `get_wearable_summary(days)`：返回日均步数、静息心率区间、睡眠摘要、体重/体脂趋势、锻炼次数；**未授权时返回可读引导，绝不编造数据**

### 🧍 体成分录入与拍照识别（P4-C）
- 健康指标登记表扩展至 20 项，覆盖体成分 9 项（体重/体脂率/肌肉量/体水分率/骨量/蛋白质率/基础代谢/内脏脂肪等级/腰围）
- 「体测批量录入」页：一次录入一组同日指标、统一打备注（如"乐刻门店体测"），落库仅触发一次刷新
- **拍照识别秤屏**：视觉模型优先（提示词输出结构化 JSON → 自动回填表单）→ 未配模型走**本地 OCR** 兜底 → 解析失败退化为手动填写提示，全程不崩溃

### � 健康档案智能管理（P7）
- **独立视觉识别服务**：识别配置与主 AI 分离（地址 / Key / 模型名存系统加密存储），保存时自动规范化地址（防双 `/v1` 导致 404）；内置硅基流动预设（`Qwen/Qwen2.5-VL-7B-Instruct`，注册送免费额度，模型名以平台「视觉模型列表」为准），也可自填任意 OpenAI 兼容视觉接口
- **三级识别降级**：① 独立视觉配置 → ② 旧通道（主 AI Key + 视觉模型，高级设置）→ ③ 本地 ML Kit OCR（仅图片、仅移动端、免费离线）；已配置但调用失败**不静默降级**，按鉴权失败 / 网络异常 / 服务错误分型提示，可重试或改用本地识别
- **报告导入**：拍照 / 相册 / 文件选择，支持图片与 PDF；PDF 逐页渲染、每批 4 页送视觉模型多图识别并按页合并（**超过 20 页引导拆分**）；未配置识别服务时图片可走本地 OCR，PDF 需配置识别服务
- **结构化提取与确认入库**：识别文本交主 AI 提取指标（数值 / 单位 / 参考范围）与总评，红黄蓝绿四灯评级——**红**＝危急 / 明显异常（就医引导，不淡化）、**黄**＝超出参考范围、**蓝**＝临界需关注、**绿**＝正常；入库前整页人工确认，可改可删
- **报告档案**：按类型（体检 / 化验 / 影像 / 门诊 / 其他）与灯色筛选；详情含 AI 总评、入库指标、识别原文与**行动清单**（可勾选完成、设复查日期）；复查到期发**本地通知提醒**（Android 13+ 首次设置时请求通知权限，数据不出设备）
- **多报告连读**：归档页选 2~8 份报告，主 AI 生成逐指标跨期对比表 + 趋势判读 + 隐蔽信号提示；无入库指标的老报告以 OCR 参与并注明
- **智能体工具** `get_health_reports`：对话中查询报告档案（列表 / 单份详情），检前可咨询加项与准备事项（引导与医生确认 / 遵医嘱），检后先灯色总览再逐项引用数值与参考范围
- **隐私与边界**：档案数据仅存本机（SQLCipher 加密），云同步为整行 JSON 同步（新列已注册服务端规格并由启动迁移补列）；AI 归纳不构成医疗诊断，异常灯色以就医为准

### � 健康数据合规（PIPL）
- **单独同意**：首次授权前强制弹出同意页，逐项列明数据类型与用途，非默认勾选；同意留痕（时间 + 文案版本号），版本变更旧同意自动失效
- **可撤回**：撤回为「撤销授权 + 清空本地快照 + 留痕」原子操作，撤回后智能体工具**立即失效**
- **最小必要**：只读、逐类型声明、无写入权限；健康数据**默认不参与云同步**（独立开关，默认关闭），大模型仅接收脱敏文本摘要

## 📁 目录结构
- `lib/services/` AI引擎、本地智脑算法、联网搜索（文献 / AnySearch 网页）、云同步（CloudApi/SyncEngine）、应用锁、循证知识库、健康数据聚合、体成分解析、**文献检索（Europe PMC/OpenAlex/Crossref/Semantic Scholar）**、**视觉识别（vision/：独立配置 / 服务 / 分型异常）**、**PDF 渲染 / 报告提取 / 复查提醒（health/）**
- `lib/providers/` 业务状态（AppProvider / AgentProvider / **WearableProvider**）
- `lib/screens/` 训练/饮食/财务/知识库（含**开放数据与本体**）/AI/云同步/锁屏/**健康（同意页/数据源诊断/体测录入/报告导入与档案/提取确认）** 各界面
- `assets/data/` 内置数据资产（**`evidence_kb.json` 循证知识库 + 疾病—运动两层关联 + 家庭用药安全库 + 核心膳食补充剂库 + 本体术语与数据源登记**；**`exercise_catalog.json` 开放动作库 2428 条**按需加载）
- `scripts/` 知识库导入脚本（`import_knowledge.py` v1.5.0）与种子（`scripts/knowledge_sources/`，含疾病—运动两层种子、用药安全种子、补剂种子、本体种子与开放动作库种子）
- `docs/` 调研报告、设计规格、实施计划（`docs/superpowers/`）、**PIA 评估（`docs/research/`）**
- `server/` FastAPI 云端服务（账号 auth + 双向同步 sync，Docker 一键部署）
- `books/` 内置书籍资源（原始文件）
- `assets/books/` 提取后的书籍文本（**打包资产，仅限公有领域来源**，见下方第三方内容声明）

**关于联网检索的取舍**：早期版本内置了抓取搜狗微信 / Bing / 百度结果页 HTML 的联网搜索，**该实现已整体移除**——它违反目标站服务条款、随时被反爬打断，选择器一改即失效，是本项目风险最高的一段代码。现分两层：学术证据走官方开放的文献 API（Europe PMC / OpenAlex / Crossref / Semantic Scholar），只取题录、不落正文；通用网页走 AnySearch 官方检索 API（Bearer 鉴权、返回 JSON），只取标题 / 链接 / 摘要片段并丢弃正文。两层均默认关闭、仅在用户显式开启后按单次提问检索，未开启时不产生任何外发请求。如不希望依赖第三方检索服务，也可改为部署自建元搜索实例（如 SearXNG，AGPL-3.0），App 只访问自己的域名。

**关于开放数据集**：`dataset_registry_seed.json` 中的条目分三种获取状态——`已接入`（数据已随包分发）、`可接入`、`登记题录`。**`登记题录` 仅记录线索，不下载任何正文数据**，单测对此有硬断言。体量较大的语料型数据集（如道教知识 RAG 约 9.6 万条、健身气功指令集 5.7 万条）属训练语料而非端上消费场景，**一律不下载、不打包**，如需完整使用应在自建服务器侧接入。

**内置书籍通道**：`books/`（原始文件）与 `assets/books/`（提取文本）**仅允许公有领域或允许分发的开放许可来源**（如《黄帝内经》等古籍）。`assets/books/` 是打包资产，其中的文本会随 APK 分发，而 `.gitignore` 只保护代码仓库、不保护发布包，因此现代版权书籍不得放入；`scripts/extract_books.py` 已内置来源白名单闸门。

**第三方软件**：Flutter 及所用 pub 包、FastAPI 等依赖均按其自身许可（MIT / BSD / Apache-2.0 等）使用，详见 `pubspec.lock` 与 `server/requirements.txt`。
